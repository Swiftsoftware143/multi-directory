🔑 Provider API Keys 📘 Full setup guide — all 23 providers →

Paste your own keys here — encrypted at rest and shown masked (first 4 and last 4 characters only; the full value never leaves the server). Every key can be named, so you can store several accounts for one provider side by side. Every key is also scoped: platform-wide, to one network, or to one directory — a directory with no key of its own inherits its network's, so one Google Places key set on the ZaarHub network serves all ten cities.

Loading providers...
⚠ Google is two keys, not one. The Google Places key on this card is used by the server for business search, discovery and data enrichment — restrict it in Google Cloud by server IP address, never by website referrer. A Maps JavaScript API key is only needed when a map is drawn in a visitor's browser; it is visible in the page source, so it must be restricted by website / HTTP referrer to your own domains, it cannot do the search job, and it belongs in the directory's Google Maps API Key (SEO settings) — not here. Do not create one “master” key with both APIs enabled: it can be tightened to neither, so one leak exposes everything. Never paste a key into a chat or a ticket — enter it here. Keys are encrypted and only a masked preview (first 4 + last 4) is shown; a blank field never means “no key” — each row says when a key is stored and when it last changed. Which key for which job? →

🌐 Domains, Subdomains & Subfolders

Serve any directory — inside a network or standing alone — on a subdomain of its network (palm-bay.zaarhub.com), on its own custom domain, or in a subfolder of a host (zaarhub.com/palm-bay). 🧭 Data Enrichment loading…

Rotating re-enrichment of phone / website / address / geo across the directory. The provider comes from Provider API Keys (Google Places · SerpAPI · Bing · Google CSE · Apify) — pick one here or leave it on auto. OpenStreetMap (free, no key) is the built-in fallback and can also be pinned here, so enrichment still runs with no paid API at all. Apify is metered and paid per use, so it is never chosen automatically: add its token on the Provider API Keys card and pin it here to switch it on. With nothing configured (or a key the provider rejects) the run records a skip/error and enriches nothing. Every source only fills empty fields — it never overwrites what an owner or admin typed. By default the auto-refresh touches unclaimed listings only: once a real owner claims a business, their data is authoritative and the cycle leaves it alone.

📦 Complete Export — one record or the whole directory

Download a COMPLETE record for one entity — a business, a supplier or a customer/user — as its own row plus every record that hangs off it (reviews, claims, loyalty, submissions, surveys, activity, deals …), gathered together rather than scattered. JSON for a machine, CSV (one section per related table) for a spreadsheet. Bulk downloads every business, supplier or customer in a chosen directory. No SQL, no script.

“Complete” is the whole live catalog: every table whose foreign key points at the record. Scoped to what you administer — an id you may not read returns a plain “not found”.

🔗 CoreSwift Sync — every entity, one record at a time

Each record keeps its own honest state (synced, error, not connected), when it last pushed and why it failed, so a run is resumable — a synced record is skipped unless you tick Force. Nothing is faked: if CoreSwift is not connected for the directory, or the hub refuses, the row says so.

👥 Audience Lists, Sequences & Media

The city's three built-in lists in one place — Subscribers (free signups), Business Listings (claimed businesses) and Sponsors (paid placements). Pick a city to see its counts and its members, and move a business up to Sponsors with one click: that also adds it to the city's Sponsors list in CoreSwift, which is what starts the sponsor nurture.
A sequence is the content and timing of that nurture (steps with a delay, subject, body and image). Multi-Directory defines it and decides the audience; CoreSwift performs the send — this panel never sends campaign mail itself.
